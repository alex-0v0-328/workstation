# Workstation 界面文案与多语言（i18n）

0.6.0 起，全部面向用户的界面文字集中在 `src/shared/i18n/` 的类型化对照表，支持简体中文（默认）、繁體中文、English (US)。本文是维护规则。

## 结构

- `zh-CN.ts`：基准字典。key 结构即契约（`Messages` 类型由此导出）。
- `zh-TW.ts` / `en-US.ts`：声明为 `Messages` 类型。**缺 key、多 key、结构不符都会编译失败**，三语对照由类型系统强制，不存在"漏翻译悄悄上线"的路径。
- `index.ts`：`Language`、`resolveMessages()`、`createT()`（`t()`）、`formatMessage()`、`MessageError`、`localizeError()`。

## 铁律

1. **任何面向用户的字符串都必须走字典**：JSX 文本、`placeholder`、`aria-label`、`title`、toast、系统对话框、托盘、通知、OAuth 回调页、校验/提供商错误。不得硬编码。
2. **新文案先加 `zh-CN` 的 key，再补齐另两语**；TS 会强制。命名用驼峰，命名空间按区块：`nav` / `todo` / `study` / `calendar` / `mail` / `editor` / `wizard` / `settings` / `validation` / `remote`（主进程）等。
3. **插值用 `{name}` 占位**：`t('shell.courseCount', { count: 3 })`。不要拼接字符串片段组句。
4. **英语单数**：`t()` 在 `count === 1` 时优先取 `<key>_one` 变体（如 `courseCount_one`）。中文两本字典的 `_one` 值与基准相同（无词形变化），英文写单数形。多计数文案（如 `{a} x · {b} y`）在英文用冒号式（`Open: {pending} · Total: {total}`）回避一致性问题。
5. **日期与数字**：luxon 一律 `.setLocale(messages.meta.locale)`；格式模板放 `time.*`（如 `time.dateShort`），不要写死 `M月d日` 之类的局部格式。数字密集处用 `font-variant-numeric: tabular-nums`（见 `base.css`）。
6. **主进程文案**用 `src/main/i18n.ts` 的 `mt()`；语言随 `workspace:save` / 档案恢复即时切换并重建托盘菜单。
7. **跨进程错误**：`shared`/`main` 抛 `MessageError('<namespace>.<key>', params)`，IPC 与视图边界用 `localizeError(e, t)` 翻译；zod 消息直接写 key 字符串。`localizeError` 对未注册 key 原样回退。
8. **属于数据的文字不翻译**：主题包的 `name`/`description`、用户内容（课程名、邮件主题）、AI 提示词与输出。AI 提示词保持简体中文（产品行为），不属于界面文案。
9. 语言切换不得重置数据、草稿或滚动位置（与主题切换同纪律，smoke 覆盖）。

## 新增一门语言的步骤

1. 在 `Language` 联合类型与 `languages` 列表（`index.ts`）、`domain.ts` 的 settings schema 枚举中加入新 locale（如 `ja-JP`）。
2. 复制 `zh-CN.ts` 为新字典文件，声明 `const xxXX: Messages`，逐条翻译（含全部 `_one` 变体）。
3. 跑 `npm.cmd run typecheck`（结构校验）与 `npm.cmd test`、`npm.cmd run smoke`。
4. 用 Electron 开发启动器逐页截图检查新语言排版（长文案溢出、徽章换行、1200/1000px 断点）。
